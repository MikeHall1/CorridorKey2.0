## Thresholds established before further measurement

- **T1 correctness:** exact frame count, requested half-open range, recorded source index, channel layout, terminal outcome and source-file byte preservation. Zero stale-cache hits in tested invalidation cases. Signed HDR values must remain finite and unclipped where float export supports them. Fixtures use independent expected pixels; numerical tolerance must match the declared operation/encoding rather than comparing a file with itself.
- **T2 performance:** brief §5 initially measures 1920×1080 at 24 fps, with configurable 30/60 fps, 1440p and 4K cases. Achieving 24 fps requires measured end-to-end uncached processing on named hardware; it is not a hardware-independent promise. Report startup, buffering, look-ahead and cached playback separately. At least three measured repetitions, alternating matched baseline/candidate order (§18); no performance claim from CPU test duration.
- **T3 precision (provisional):** for a behavior-preserving float change, normalized alpha MAE ≤1e-4 and maximum error ≤1e-3 against the declared full-quality baseline; float16 changes MAE ≤1e-3 and maximum ≤1e-2. Assumption: [0,1] coverage, matching deterministic settings and no changed conditioning. Establish baseline repeatability first; a baseline outside these bounds requires investigation, not automatic relaxation. Foreground/HDR tolerances depend on reference dynamic range and must be declared before their experiment.
- **T4 quality (provisional):** no category median or worst-case normalized reference error regression above 5% for behavior-preserving optimizations, subject also to T3 and structured visual review. A zero baseline requires an absolute tolerance declared before measurement. This is a regression screen, not a definition of professional quality. Enhancement/approximation acceptance requires paired accuracy, temporal, composite and blinded visual review; explicit quality tradeoffs cannot be hidden by averaging categories.
- **T5 resources (provisional):** retained cache payload never exceeds the configured byte budget; zero budget retains zero payload. Separately measure active tensors, staging, RAM, VRAM and temporary disk. Ten repeated jobs after warmup should show no unexplained persistent RSS increase above max(128 MiB, 10% warm RSS). The allowance accommodates bounded allocator retention; any upward trend or leaked owner remains a defect even below the allowance. Whole-process and host-shared budgets are separate unfinished requirements.
- **T6 interaction (provisional):** callbacks schedule owned I/O rather than performing hashing/decoding/sealing on the GUI thread. Cancel/close must preserve ownership until actual terminal delivery; blocking native calls must be reported. Initial engineering target for ordinary interactive callbacks is <100 ms on the declared test machine, excluding explicit modal file dialogs; this latency target remains unmeasured until instrumented. Cancellation must not misreport a committed output as absent.
