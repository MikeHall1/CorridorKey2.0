# Native desktop workspace

Launch with the requirement-compatible interpreter used by the engine:

```sh
python -m pip install -r requirements.txt -r requirements-desktop.txt
python -m corridorkey.desktop
python -m corridorkey.desktop --project /absolute/path/project.json
```

Use an isolated environment. `--help` does not import Qt, Torch or model code. Missing optional Qt produces an actionable startup error. The present macOS environment can inspect sources/settings and run CPU preview/controller tests; production inference still requires CUDA and the existing local model/foundation assets. No model download, CPU/MPS neural fallback or bundled release is introduced.

## Working workflow

1. Open a video or naturally ordered frame directory, or drop one local path. Choose an output parent. Each queued render gets a new UUID child directory; a later render does not overwrite an earlier job. Keep sources/hints/corrections/assets stable while jobs are queued or running.
2. Select **Preview** to decode the requested zero-based source frame. The decoder runs off the Qt event thread, independently of the inference worker. Source frame preview is separate from model inference. Unsupported/corrupt sources produce actual errors.
3. Choose full quality or explicit **Quick Key draft**. The latter selects offline interval5, stop-on-uncertainty and source-RGB foreground; edit advanced settings for other supported modes. Full quality resets Quick Key-only cut/reset/adaptive/gap controls; an attached correction document remains. All inference, hints, cache, precision, colour, output and writer settings remain editable by their existing core names. Settings are validated before submission, then snapshotted; later editor changes do not change queued jobs.
4. The frame limit and video start choices use existing `num_frames`/`start_mode` semantics. Zero in the limit widget means all frames. Frame directories support begin only. Source In/Out (exclusive) now provides explicit trimming; Mark stages the preview position and Apply changes future settings. The viewer position alone does not change the render range. See [source ranges](source-ranges.md).
5. Add renders, select queue rows, inspect actual stage/completed/total events and diagnostics, and cancel selected jobs. Work counts are not necessarily frame counts. Cancellation remains a request until a terminal event arrives. The queue executes one job at a time in the shared worker, retaining its normal session/model. Default worker capacity is four waiting jobs; a full queue is explicitly rejected. The desktop command queue is bounded8 and row history128; **Clear finished** frees history only, never deletes outputs.
6. Select a completed row for alpha, foreground, checker or solid-colour composite previews. Views read that job's actual exports and original settings, not current editor settings. Missing exports fail explicitly; no placeholder matte/foreground is synthesized. Composites require straight foreground RGB and coverage alpha with matching geometry/count; compositing uses linear light, followed by sRGB display. EXR is treated as scene-linear per the current engine contract. This is not a managed arbitrary-primaries/OCIO viewer.
7. Pin a displayed thumbnail as **A**, then preview another job/frame/view as **B**. A keeps its pixels and source/view/frame label. Match frames/views and processing conditions for a meaningful comparison. This pin is a fixed display snapshot. Alternatively, Selected render as synchronized A moves both panes through recorded source coordinates; see [source ranges](source-ranges.md). Neither mode certifies quality or VFR timing. HDR/negative RGB clips only in the display conversion; alpha coverage receives no RGB transfer function. Source premultiplied decoding uses the explicit core setting.
8. Save/reopen a local project to preserve all core/writer settings, source/output/hint/correction paths, profiling flag and preview-frame index. Reopening never renders or replays jobs. Strict finite/duplicate/field/version/size validation applies. Projects cannot overwrite source/hint/correction paths or be saved inside those source directories. Referenced media and correction files are not copied; existing correction-content/provenance validation still applies at render. Projects do not embed queue journals. Default queue history/results are session-local; optional Queue history workspaces persist observed requests/events separately, and A remains session-local.

**Stop worker** requests cleanup asynchronously, cancelling active/pending work. **New worker** requires the previous bridge to finish, consumes its final records and never resubmits old jobs. Connection loss stays `lost`, with possible partial outputs. Worker cleanup uncertainty remains explicit. See [worker.md](worker.md) for cooperative/native-call limits and platform containment. The window stays responsive while the owned worker shuts down. CPU preview decode is a daemon thread with a latest-only pending request/result; a blocked native decoder cannot be forcibly interrupted here. Native input decoding still allocates the full frame before making a <=1280px thumbnail, and directory discovery stores its filename list. These are thumbnail/queue bounds, not a total RAM/VRAM budget.

Video viewing uses OpenCV's existing uint8 decode and indexed seek; frame accuracy on VFR/long-GOP material, timing metadata and high-bit/HDR video remain unvalidated. Single images can be inspected, but render inputs remain the core's video/frame-directory contract. Source and export viewer frame indices are independent; partial video render offsets are not automatically aligned for A/B. Source display uses explicit frame-directory linear/association settings and does not predict the eventual neural result.

## Framework decision and dependencies

Qt Widgets uses maintained Python bindings, native widgets, file dialogs, local drag/drop, image buffers and an event loop without introducing another inference language or implementation. The frontend depends on **PySide6-Essentials6.10.2** and matching shiboken6; Qt Addons/QML/WebEngine are not needed. Qt's official [getting-started guide](https://doc.qt.io/qtforpython-6/gettingstarted.html) documents installation and [deployment guide](https://doc.qt.io/qtforpython-6/deployment/index.html) documents supported packaging routes. A bundle recipe and license/redistribution review remain required before distribution; choosing Qt is not a release acceptance claim.

The existing Tk9 installation actually failed initialization with NaN display scaling/macOS service restrictions. PySide6 was absent; the initial sandbox pip attempt could not resolve PyPI. The isolated temporary environment then installed the pinned Essentials binding through an approved network escalation. No global installation, user `.venv` modification or upstream runtime-dependency upgrade occurred. Headless engine users do not need Qt.

## Actual verification and remaining work

Milestone18 tests use real offscreen Qt widgets/event processing and an actual owned child, with explicit test-only deterministic rendering for native EXR export, immutable queued settings, cancellation and hard-crash/new-worker handling. Preview tests exercise natural ordering, native uint16, coverage/no gamma, actual linear EXR composites, invalid/mismatched exports and display-only clipping. Project tests cover full settings roundtrip, source protection, strict nested JSON and oversized files. A/B tests retain actual pinned pixels, and UI tests catch invalid-setting labels and range synchronization. Optional Qt tests explicitly skip when the binding is absent; the verified isolated environment has it installed.

`benchmark-results/desktop-m18-generated/summary.json` and `workspace.png` capture a generated uint16 source preview/A snapshot and the **real production worker's CUDA-required failure**, with clean worker/preview shutdown. This validates unsupported-backend presentation, not inference success. The image was inspected locally. All source/media stays local.

Interactive Cocoa/Windows desktop behavior, real OS drag/drop dialogs, high-DPI/accessibility, packaged startup, Windows cleanup, pretrained GPU performance and visual key quality remain **NOT VERIFIED**. The offscreen plugin's size-hint message is a plugin limitation, not evidence of native-window acceptance. Live GPU/process-tree memory telemetry is unavailable and labelled accordingly.

# Completed-render native caches

Select one completed queue render and **Prepare OFX cache…**, choose an existing destination and Prepare. The panel uses that immutable record's source range and actual EXR exports, independently of unsent form edits. Hash/decode/seal work stays off the interface thread; progress/cancellation and safe workspace close are owned until actual completion. Copy path is explicit. Invalid selection disables old preparation. This experimental manual cache workflow requires matching source, host frame offset and scene-linear colour settings in Resolve; automatic host validation is unavailable. See [OFX cache](ofx-cache.md) and [verification limits](code-health.md).
