# Sampled worker-tree resident memory stop policy

The policy is locally verified on macOS, including owned child processes and actual session/recovery workflows. It provides cooperative stopping at observed checkpoints, not a hard RAM cap or a guarantee against memory exhaustion.

Set **Common job settings… → Engine → Worker tree RSS stop bytes** for future jobs. Blank/null disables the policy. Exact integers from0 through9223372036854775807 are supported;0 is a literal threshold and will normally refuse a live process before model loading. The CLI setting is `--process_tree_rss_stop_bytes`; batch, advanced JSON and immutable queued job requests use the same field.

The shared session checks current resident memory for its owning process and tracked descendants. It samples before admission, before and after model loading or reuse, at cooperative cancellation/progress checks, and before successful completion. Ordinary samples are throttled to approximately250ms. One observer and guard are shared with the recovery controller so source/asset hashing, verified-existing replay, cache restoration and publication also use the requested per-job threshold. Workspace initialization and teardown are outside that per-job policy.

The observer pins process ownership to PID plus birth identity and follows observed descendants, including known children that later reparent. It bounds traversal and native enumeration. Missing permissions, inconsistent identity, unsupported providers, malformed data, traversal limits and incomplete measurements return unavailable totals. Required unavailable measurements fail explicitly rather than becoming zero or falling back to lifetime high-water RSS.

Available RSS values are summed across observed processes. Shared resident pages can count more than once. A sample does not cover the GUI or Resolve when those processes lie outside the worker tree; it excludes GPU allocations, other applications and total machine usage. Short-lived children and peaks between samples can be missed. Native calls may allocate, block or exhaust memory before the next checkpoint. Deadline checks around native sampling calls do not forcibly interrupt the operating system.

Exceeding the threshold raises `ResourceLimitError`; inability to establish the required measurement raises `ResourceMeasurementError`. Both produce failed jobs with no success FPS. They do not select another backend, precision, memory mode or approximation. Existing ownership cleanup handles touched models, writers and temporary mappings. An untouched healthy cached model is preserved when a new job fails preflight. A failure does not erase previously completed exports or rewrite successful historical recovery records.

Cached diagnostic snapshots include the requested limit, interval, sample count, latest observation, observed peak and triggering failure. Final error reporting does not make another OS query, so an observation error cannot replace a primary processing failure during cleanup. Existing lifetime peak RSS snapshots remain separately labelled and unchanged.

Provider implementations use macOS libproc, Linux procfs or Windows process APIs without adding a dependency or changing global environment/allocator settings. Actual target verification is required for each provider; injected platform records do not establish native compatibility. Existing static findings, GPU shared-memory budgets and whole-machine resource acceptance remain separate open requirements.
