# Desktop correction authoring

Launch `python -m corridorkey.desktop` in the compatible environment with optional `requirements-desktop.txt`. Select a real video or frame directory and the desired core range/FPS/colour settings. Use **Corrections… → Edit attached / new document**, then choose a project parent outside the source directory. **Open correction document…** reopens a saved core correction document against the currently selected source/timeline. Close the current editor before binding another document/source. Existing desktop projects preserve the attached correction path; reopening a desktop project does not execute a render.

The editor calls the existing source probes, `CorrectionDocument`, `CorrectionHistory` and `CorrectionRasters`. Source hashing/probing, mask validation/encoding, history publication, save/reopen and frame decode run on one background owner. It does not load another neural model, introduce a CPU/MPS keyer or change full-quality inference. Missing CUDA still prevents neural rendering. Native OS dialogs/drag/drop, target packaging and real GPU/visual acceptance remain separately unverified.

## Painting and editing

The frame index is relative to the selected clip. Video start/count comes from the same deterministic core probe, including middle/random-middle and seed; frame directories retain begin-only restrictions. The displayed-frame label records the selected index and original source start. Source preview uses the existing display conversion and is not a neural result. Native dimensions remain authoritative even when the display fits a smaller widget; paint coordinates account for scaling and letterboxing, and strokes outside the image are ignored. Brushes are binary native regions with an integer pixel radius. Erase draft removes paint; Clear draft discards only uncommitted paint.

Choose the operation, authored frame, strength, direction and half-open `[start,end)` range, then paint and **Commit brush**. Commit creates a native binary uint16 PNG (0/65535, exactly representing painted0/1), hashes and validates it through the shared raster implementation, and adds an ordered correction entry. This is not a new neural brush channel. Full-frame **matte** uses zero coverage outside the painted region; **keep/remove** act only in painted regions. Use **Import mask…** for native soft grayscale/RGBA-alpha masks, including float EXR/uint16; their original encoded bytes are verified and copied without recompression or quantization. RGB luminance masks, geometry mismatch, invalid coverage and changed asset bytes fail explicitly. Newly chosen strength values have the widget's0.001 granularity; existing imported strengths retain full precision when that field is untouched during other edits.

Blue shows an uncommitted draft; green shows the selected saved asset's coverage when the viewed frame is inside its range. The overlay is an authoring aid, not predicted alpha, confidence, tracked motion or proof of improved key quality. Only the selected stored raster is shown; it does not pretend to combine every operation into a neural preview. The exact shared operation equations and hint/carry/flow limitations remain in [corrections.md](corrections.md). Directional ranges repeat a static mask, not optical-flow brush tracking or reverse inference. Both-direction conditioning still respects the existing model's actual hint channels.

Load frame explicitly to move the displayed source. A brush can be committed only to the frame actually displayed. Commit/Clear a draft before changing history, importing or saving; closing refuses to discard a dirty draft. New mask clears selection and prepares a one-frame range without deleting committed entries. Selecting a row populates its metadata; Update selected changes supported metadata, Delete removes it, and Move up/down changes composition order. For reset rows only the frame is editable; use a new raster entry for a different kind.

Add reset inserts an actual core temporal reset. Split shot adds an interior shot boundary, and Merge at frame removes one. Existing raster ranges must stay inside a declared shot; contradictory splits/ranges fail rather than silently trimming an authored mask. Reset/shot behavior, authored anchor promotion and direct constraints remain shared with CLI/batch/recovery. Undo committed / Redo committed operates on document edits (not individual unfinished brush strokes), including order, range, shot/reset and raster changes. New edits after undo discard the live redo branch and use a monotonically increasing new revision.

## Persistence and invalidation

Each editor owns a new `corrections-UUID` directory under the selected parent. Newly imported/painted assets have unique names. Every successful committed edit and selected undo/redo revision publishes an atomic immutable `edit-rREV-UUID.json` recovery snapshot, displayed in the window. Close keeps these artifacts. Reopen one through Open correction document after selecting the same source/timeline. The editor retains128 live document snapshots (up to127 undo transitions); older on-disk snapshots/assets remain and are never silently evicted or deleted. Live undo/redo history is not automatically reconstructed across process restarts; reopen a chosen saved revision explicitly.

**Save snapshot & attach** rechecks the complete source hash and all asset hashes, then publishes a new immutable `corrections-rREV-UUID.json`. It attaches that path only if the workspace source/range/FPS/seed still agrees with the editor's bound job. A mismatch leaves the saved file intact and reports the attachment error. Existing queued job settings keep their original correction paths; subsequent saves never overwrite those manifests. Explicitly enqueue new work for a new correction version. Keep queued source/hint/model/document/asset files stable: this is not a globally atomic filesystem snapshot or protection against external edits. Reopened existing documents can still reference their original external assets, whose hashes are verified; newly imported assets get private immutable copies.

The existing core invalidation function conservatively marks entire affected declared shots. Source/timeline/shot-partition changes invalidate the full extent; recurrence, carried hints, anchor placement and bidirectional dependencies are not reduced to a small pixel neighborhood. The window displays the **last edit's** invalidated ranges. New document identities enter existing runtime/recovery provenance and cache keys; new GUI jobs get fresh output directories. Old completed exports remain historical results rather than being relabelled as the new correction. No automatic render/replay, output deletion or silent reuse of old corrected results is introduced.

If snapshot publication fails, the selected model/history remains unchanged; failed undo/redo publication restores the old cursor. An encoded private staging brush is cleaned up, and already published authored assets/snapshots are retained. Native filesystem/image calls are not forcibly interruptible by a thread. Main workspace close waits asynchronously for the editor owner to finish/cancel; a dirty draft must be committed or explicitly cleared first.

## Bounds and actual verification

Correction documents now reject duplicate JSON keys, nonfinite/exponent-overflow values and raw files above4MiB, with matching admission before atomic save. This stricter core read/save contract is shared by all entrypoints; existing valid schema1 files keep their semantics. A save that exceeds the limit preserves an existing destination. The default standalone `CorrectionHistory` remains unlimited unless `max_snapshots` is supplied; only this editor selects128. Editor native canvas admission is64×1024×1024 pixels, with an actionable error for larger material; core raster documents/CLI remain available. This is an editor allocation bound, not a whole-process memory cap: probing can decode a full source frame first, source/native brush/encoding buffers and up to two float32 core masks are additional memory, and source file lists/history metadata also consume RAM. Authored snapshot/assets are durable user work, not an LRU cache; disk growth is not automatically capped.

Actual CPU tests cover source/native binding, exact imported float bytes, native brush constraints, save/reopen and unchanged earlier manifests, full-shot invalidation, bounded live undo/redo/branching, failed checkpoint/cursor restoration, strict read/save admission, source changes, inactive ranges and precision-preserving metadata edits. Actual offscreen Qt tests also reject commands before the initial bound UI snapshot; mouse events verify native pixel mapping/letterbox exclusion, brush/eraser, dirty-close guard, reset/shot/range controls and attachment refusal after timeline changes. An actual owned child with an explicit test-only constant-alpha engine receives original/first/second queued settings and writes native EXR values0.5/1/0 using the shared correction operator. That proves authoring/controller/export effects, not pretrained inference quality.

`benchmark-results/correction-m20-generated/summary.json` and `editor.png` capture a generated320×180 uint16 source, two immutable saves, keep/remove/reset entries, shots, unchanged source/old manifest and actual clean owner shutdown. Actual shared CPU math on supplied alpha0.25 produces0.8125/0.125/0.25 in the intended regions. The production worker validates the attached document then actually fails unavailable CUDA; neural FPS/quality remain null/unverified. The editor screenshot was inspected locally.

No training, reverse neural pass or professional visual-quality claim is made.
