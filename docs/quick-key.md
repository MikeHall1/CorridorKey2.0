# Quick Key draft approaches

Quick Key is opt-in through the shared CLI/session/batch engine. It is an approximation for visualisation; full-rate mode remains the default. On this Mac, the orchestration is CPU-tested with deterministic neural substitutes. No real-model draft inference, GPU speedup or held-out visual quality has been validated.

```sh
python infer.py --input /local/clip.mp4 --output_dir /local/draft \
  --quick_key --quick_interval 5 --quick_context_radius 2 \
  --quick_fallback stop --diagnostics /local/draft/job.json
# Add known shot boundaries, relative to the selected clip:
# --quick_cut_frames 120 240 --quick_reset_frames 360
```

Interval 1 with the default approach/options uses the original full-rate inference/render path, including reconstructed foreground. Its CPU fixture outputs match a Quick-Key-disabled run. Sparse Quick Key outputs are named `*_source_rgb_draft*`; every RGB output uses the actual current source, including at anchors. Foreground output is source RGB rather than the model's reconstructed foreground. Cutout/checker retain the explicit existing despill strength, and alpha remains coverage. EXR float source RGB retains signed HDR values without a bfloat16 model roundtrip. Preview outputs retain existing display/linear and clipping contracts. Sparse alpha loss must be evaluated separately from substituting source RGB for reconstructed foreground.

## Temporal strategy and work

For each shot/reset segment, regular anchors are 0,N,2N relative to its start. Offline/hold mode also adds the final frame. Causal mode omits final-frame anchors inferred from future cut/end knowledge; past-only propagation does not require a future endpoint. `quick_max_gap` inserts extra anchors without restarting the regular schedule, including the causal tail of a segment. Known cuts/resets begin a new segment and are mandatory anchors; propagation/context/carry do not cross them. Frame indices are relative to the selected clip, not the original untrimmed video. Known cuts can be supplied; optional `--quick_auto_cuts` additionally analyzes adjacent reduced display proxies before neural processing. Detected and supplied cuts are unioned without mutating requested settings. The detector scores the maximum of mean RGB change and mean per-channel histogram total-variation distance, with a 0.1 mean-RGB-change gate. `quick_cut_threshold` defaults to 0.35, `quick_analysis_max_side` to 128. These uncalibrated candidates can flag flashes/exposure changes and miss semantic cuts. `*_shot_analysis.jsonl` retains each score, and job diagnostics record scan time, decode count, supplied/detected/effective boundaries and interruption status. The scan is opt-in, adds a complete decode pass, and is not proof of shot correctness. Active authored correction/reset frames from `--corrections` are mandatory anchors. Ordered native raster effects and supported hint/carry/flow conditioning are described in `corrections.md`.

Stage 1 evaluates contiguous native-rate windows around anchors (radius 2 by default). In offline/hold mode, identical context ranges are evaluated once. Overlapping baton predictions are blended using the existing taper/normalisation machinery; Stage 2 evaluates only scheduled anchor frames. Stage 1 sees `t_stride=1`, never a compressed sequence of sparse frames. Causal mode instead uses the anchor and at most `radius` previous native frames; only that context contributes to its owned anchor. Later windows cannot blend future information into an earlier causal baton. Stage 2 in the inspected implementation flattens B×T and refines frames independently, without temporal attention. A radius of 0 requests independent single-frame contexts. The largest context must fit the effective `hann_chunk`; otherwise inference fails with instructions to adjust chunk/radius. Hann stride still governs full-rate mode; sparse mode derives windows from anchors and radius.

RVM runs chronologically over all selected frames once, resetting at supplied/detected cuts and resets even when they fall inside a prefetched source chunk. Predicted hint carry is limited to overlapping native indices and reset at segment boundaries. Existing first-frame/full hints are retained. Causal mode uses one-frame RVM chunks so a newly detected future cut cannot change earlier feature batch boundaries; this may add overhead. Low-VRAM mode still precomputes IID features for **all** frames and uses disk batons; sparse mode does not promise to reduce that prepass. Optional bounded RAM IID reuse is unchanged in normal mode.

All anchors and the chronological prepass finish before output assembly. All approaches retain this offline staging and substantial startup latency; none is a zero-startup/live preview. Hold uses the last available matte and no motion; causal propagation uses only a past anchor and the current proxy (forward/reverse flow between those two times), with no future matte lookup. Its zero propagation look-ahead does not imply a live runtime. Hold retains symmetric offline neural contexts and must not be described as a causal neural pipeline. `max_look_ahead_frames` describes the propagation bracket only; it excludes the complete precompute/startup dependency. First-rendered-batch wall time includes these prepasses. Total live latency remains unavailable.

## Motion and explicit uncertainty policy

For each non-anchor frame, CPU Farneback estimates current-to-left/right and reverse flows on an explicit display RGB proxy. Grayscale motion estimation uses at most `quick_flow_max_side` pixels on the longest side; displacement components are scaled back to native coordinates. Both anchor mattes are warped toward the actual current source time, then weighted by temporal distance and diagnostic reliability. No complete source frame is interpolated.

The implementation follows OpenCV's documented [dense-flow API](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html) and [destination-to-source remap convention](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html). Reliability combines in-bounds sampling, forward/backward flow consistency and RGB proxy residuals. Defaults are a 1.5-native-pixel consistency scale, 0.15 photometric scale, minimum reliability 0.2 and maximum alpha disagreement 0.25. These are uncalibrated heuristics, **not confidence** or quality guarantees. HDR RGB remains separate from the clipped motion proxy.

Any uncertain pixel invokes the selected policy:

- `stop` (default): fail with the frame index and uncertain fraction; partial outputs remain identifiable.
- `approximate`: at uncertain pixels, retain the maximum of the propagated matte and the temporally nearest unwarped anchor matte. This explicit conservative/hold approximation can retain unwanted foreground or ghosting. It does not claim equivalence to neural inference.
- `neural`: evaluate an additional contiguous native context and Stage 2 frame, borrowing the already chronological RVM features. Fallback starts fresh local Stage 1 carry. In offline mode it becomes a propagation anchor when `quick_adaptive` is enabled; causal mode always promotes the requested neural result as its latest available past anchor. It may incur device transfers/repeated decoding; it is not bounded live-latency work.

`--quick_approach offline|hold|causal` selects offline bidirectional interpolation, hold-last-matte, or causal past-to-current motion. Hold is explicitly a labelled diagnostic approximation and does not use flow or reliability fallback. All modes export current-source RGB rather than reconstructed foreground.

`--quick_adaptive` requires sparse Quick Key and explicit `--quick_fallback neural`; it is rejected for hold. In offline mode uncertain flow/disagreement or fast motion requests an additional neural frame and promotes it for subsequent interpolation. Causal mode already promotes necessary uncertainty fallbacks; adaptive additionally requests fast-motion anchors. Fast motion is the 95th percentile of native backward displacement divided by the image diagonal (max of left/right in offline mode), threshold `quick_motion_threshold=0.05`. Small moving subjects can be missed; this is a diagnostic policy, not calibrated motion confidence. Promoted anchors are discarded/reset across shot boundaries. `planned_anchors`, actual `anchors`, `promoted_anchors`, reasons and every extra neural evaluation are recorded. Existing native-context/prepass costs remain in the work totals. No latency-budget guarantee or GPU speedup is implied.

Causal diagnostics include age since the last anchor and `drift_diagnostic = 1 - mean_reliability`. This tracks an uncalibrated reliability deficit, not measured geometric drift. Authored correction documents are implemented; GUI diagnostic overlays and the correction editor remain unfinished.

## Diagnostics, bounds and validation

Job records include actual Stage 1 window/frame-instance counts, Stage 2 frame evaluations and RVM frame evaluations. `quick_key` records anchors, fallback/extra-neural frames, flow evaluations, motion wall time, bracket look-ahead, source decode counts and IID cache snapshots for each pass. `foundation_passes` records additional normal-mode extraction work; the ordinary foundation cache snapshot refers to the initial pass. Motion timing includes proxy conversion/flow/warp/blend, excluding additional neural fallback, rendering, logging and encoding.

`*_quick_key_frames.jsonl` records per-frame anchor brackets, look-ahead, reliability/disagreement/uncertainty and chosen fallback. Entries describe rendered frames **before** writer submission, not completed durable output. Successful job completion still requires writer finalization and native frame-count checks. Detailed uncertainty masks exist in the CPU motion API; GUI overlays are not implemented.

Offline output assembly retains at most two anchor sources/mattes; causal retains one source/matte and hold only a matte. These are retained-state bounds, separate from current/flow arrays. Current source and motion working buffers are additional allocations. Anchor alphas are stored in a job-local float32 memmap. Sparse source/hint windows decode necessary video gaps without retaining/preprocessing them; frame-directory readers jump directly to needed paths. Low-VRAM Stage 2 gathers only requested anchors. These are bounded retained windows, not a total RAM/disk budget. Cancellation is cooperative around windows/flows/batches/writer waits; current native/GPU calls cannot be forcibly interrupted. Cleanup closes maps/readers/traces on success and failure.

The 9-frame CPU orchestration fixture (interval 4, context radius 1) performs seven Stage 1 frame evaluations and three Stage 2 evaluations; full-rate uses sixteen Stage 1 frame instances and nine Stage 2 evaluations. Four uncertain-frame neural fallbacks increase sparse work to nineteen Stage 1 and seven Stage 2 evaluations. These are real fixture work counts with neural substitutes, **not measured speedup**. Low-VRAM IID extraction still evaluates nine source frames. Actual Farneback alignment is separately tested on generated textured translation; known fields test native displacement scaling, disagreement and disocclusion diagnostics. CPU scheduling covers intervals 1,2,3,5,8,10, short/final segments and correction/reset points.

Additional CPU tests cover cut analysis and real recurrent reset values, maximum gaps, adaptive promotions, hold/causal frame assembly, motion triggers, and changed-future invariance with a new detected cut in both memory paths using context-sensitive neural substitutes. In the flashing 9-frame fixture adaptive promotion requests two extra Stage 2 frames versus four without promotion; that work-count difference is not visual-quality or GPU performance evidence.

Next: broader motion fixtures/reference metrics, correction UI/durable recovery, and eventually a streaming/live runtime. Cut heuristics, real-model causal behavior and runtime timing still need validation. GPU comparisons require weights, permitted reference footage and actual hardware; include cuts, hair, motion blur, transparency, fast motion, occlusion, corrections and final partial intervals, then measure frame count/FPS/export timing and at least three alternating baseline/candidate runs.

Correction masks use separate raw neural alpha, both-direction flow conditioning and final ordered output constraints. Forward/backward static raster values stay out of flow state; exact soft-strength constraints apply once directly to neural frames. Correction/reset/shot changes may still affect the full temporal shot through hints, recurrence or anchor scheduling, so invalidation is conservative. See `corrections.md` for accepted schema and explicit limits.
