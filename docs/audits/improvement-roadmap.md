## Safe subsequent OMX lanes

1. Safety owner: WP01 plus reporting-admission WP05; same shared file owner.
2. ML owner: WP02 then WP04 then reader allocation WP05; coordinate `foundations.py` and `video_io.py` explicitly.
3. Qt owner: WP03 then WP06; own lifecycle/playhead integration only.
4. QA/release owner: WP07, documentation evidence and target-platform preparation; no concurrent application writes.

With four total slots including coordinator, run at most three child lanes; use at most two simultaneous implementation workers under repository policy. Independent reviewer checks stable integrated batches, not moving files. No new supervisor or unbounded Ralph loop. Low-cost agents suit deterministic tests, inventories and docs; use current supported defaults rather than guessing unavailable models.

## Release gates

**Gate A — safe controlled tests:** WP01–04 confirmed correctness/security defects fixed; regression proofs pass; originals preserved. **Gate B — beta candidate:** WP06 connected UX, CI, actual CUDA footage and Windows bundle evidence. **Gate C — release candidate:** measured quality/performance, failure recovery and actual Resolve requirements accepted, release/legal inventory reviewed. Production approval requires sustained target-platform evidence, not this source audit or a large CPU test count.
