# Quality evaluation guidance

GPU inference, visual quality and CPU/GPU agreement are unmeasured. Existing finite-data default colour/despill and full-rate neural settings are retained; new optional spatial/screen-aware controls are unvalidated quality hypotheses. No quality enhancement has been claimed.

For alpha in [0,1], normalized MAE (and normalized SAD) is sum(abs(pred-reference)) divided by evaluated pixels across frames. Report image/frame count and units. Boundary MAE uses a declared reference-boundary band width and mask population; gradient error compares declared finite-difference kernels/scales. Foreground RGB error uses declared transfer/primaries/range and a valid-foreground reference mask; composite error uses the same linear-light background/reference. Motion-compensated temporal error must name flow/occlusion masks and be paired with accuracy, since frozen mattes can appear stable. No reference means null/unavailable, never zero error. Alpha metrics are implemented as described below; Linear foreground/composite metrics are implemented below; motion-compensated temporal alpha metrics are implemented below; real validation remains open.

Evaluate on both green/blue screens, hair/fur, blur, smoke/glass, partial transparency, fine geometry, reflections, spill, matching subject colours, poor lighting/shadows, occlusions, camera moves and cuts. Include held-out clips, per-category and worst-case regressions, blinded A/B review and black/white/grey/saturated/photo composites.

Current colour boundary: display-coded video is OpenCV eight-bit RGB with assumed sRGB transfer/BT.709-style preview metadata; no automatic primaries/transfer detection. Linear EXR is explicit (`--frame_dir_linear`); foundations use an SDR proxy while model RGB is signed asinh. RGB transfer must never apply to alpha. Cutout defaults to straight RGB plus coverage; explicitly selected linear EXR premultiplied output is implemented and labelled. Preview video clips RGB to [0,1]; float EXR retains negative/above-one RGB; half saturates outside +/-65504. EXR alone does not certify colour management. Decoded uint16 image levels are normalized into float32 without eight-bit quantization, before the inherited model bfloat16 conversion. High-bit video decoding and broader colour-management support remain work.

Quality backlog from brief §10: arbitrary-frame hints, cuts/resets and protection masks can start with existing interfaces; trimaps/edge/high-resolution refinement, temporal/occlusion stabilization, bidirectional and selective multiscale processing require dedicated algorithms and validation; screen-aware/edge-weighted/luminance-preserving despill and foreground protection require colour fixtures; explicit colour/precision/association require I/O reference tests; transparent-object refinement, selective difficult ranges and fine-tuning need suitable data (training for fine-tuning). These are hypotheses, not promised improvements. Smoother/sharper does not imply more accurate.

See `colour.md` for implemented association, linear-Y/screen/edge despill, spatial alpha filtering and invalid-value policies. Generated composite/math fixtures and neural substitutes do not prove photographic/held-out accuracy. Alpha reference metrics and array comparisons are implemented below; streaming alpha export integration is implemented below, other reference metrics remain next, and real GPU/host colour validation remains external.

## Implemented reference alpha evaluation — milestone 9

`corridorkey.evaluation.alpha_metrics` accepts normalized finite H×W or T×H×W alpha and an optional boolean evaluation mask. No resizing, clipping, integer normalization or colour transfer is implicit. Accumulation uses float64. MAE is absolute-error sum divided by evaluated pixels across all frames; normalized SAD is explicitly the same quantity. Raw SAD is also reported, labelled as an alpha sum, and must not be compared across unequal populations. Empty masks and missing references produce unavailable/null values, never a fabricated zero.

Boundary MAE seeds all reference partial-coverage pixels and both sides of four-connected transitions at alpha ≥0.5, then dilates spatially by the declared Chebyshev radius (default 1, integer 0..64). It intersects with the evaluation mask. Gradient MAE compares signed forward x/y finite differences, with no padding or scale factor; each valid neighbor pair contributes once and both endpoints must be in the mask. Its denominator is valid pairs, not pixels. No boundary/pairs means that particular metric is unavailable even if overall MAE is measurable. These declared kernels are not claimed to reproduce a named benchmark's Sobel/trimap score.

`compare_alpha` evaluates candidate/baseline against identical reference/masks and reports candidate-minus-baseline errors (negative means lower error for these arrays). The local CLI reads only `.npy` arrays, rejects pickle/ZIP containers, hashes inputs, records shape/dtype, checks that inputs did not change while reading, writes atomic JSON and prevents overwriting any input with the report:

```sh
python -m corridorkey.evaluation --candidate candidate.npy --reference reference.npy \
  --baseline baseline.npy --mask valid-mask.npy --boundary-radius 1 \
  --output benchmark-results/alpha-comparison.json
```

Omit `--reference` to obtain explicit unavailable metrics; a supplied nonexistent reference is an error. Baseline and mask are optional. This is an in-memory array evaluator, intended for bounded fixtures/short arrays; image sequences now have the explicit streaming path below; encoded video remains unsupported. It does not decode media or infer alpha from RGB. Input hashes provide content identity, not reference authorship or permission evidence; use the sequence manifest below to record reference provenance/permitted usage.

Eight analytical/CLI tests cover known error/population values, spatial-only boundary bands, masks/empty populations, missing references, invalid inputs, baseline deltas, content hashes, input protection and pickle/ZIP rejection. A generated two-pixel CLI fixture measured candidate MAE 0.25, baseline MAE 1 and delta −0.75 (`benchmark-results/alpha-m9-generated-comparison.json`). This demonstrates arithmetic/report plumbing, not photographic accuracy or an algorithmic improvement. Foreground/composite array/stream/media metrics are implemented below; flow-and-occlusion-aware temporal metrics and held-out/blinded visual acceptance remain unfinished; subsequent sequence/provenance/export integration is described below.

## Streaming media evaluation — milestone 10

`AlphaAccumulator` and `compare_stream` combine float64 error sums and integer populations across frames; they never average frame means. The metric dictionaries now expose `error_sum` for normalized errors so aggregation preserves the numerator. Only metadata scales with sequence length; decoded image buffers stay bounded. Tests compare masked streaming/batch values with unequal mask populations, check weakrefs for retained arrays, reject empty/unequal streams and geometry changes, and exercise cooperative cancellation. This does not establish a fixed total-memory ceiling for arbitrarily large individual images.

`python -m corridorkey.evaluation_media MANIFEST --output REPORT.json` evaluates an explicit aligned frame list, using the schema in `benchmarks/suites/alpha-sequence.example.json`. Populate local paths and actual provenance first. Frame IDs are increasing nonnegative integers and can select a subset; there is no implicit filename sorting, temporal alignment, resize or frame-rate inference. FPS must be positive/finite. Each optional reference/baseline/mask role is present for every selected frame or absent for the whole sequence. References require declared author, origin, permitted use and split (`synthetic`, `development`, `held_out`); these fields record the user's declaration, not independent licence or ground-truth verification. Missing references remain unavailable.

Supported assets are normalized H×W `.npy`, PNG and EXR. PNG uint8/uint16 coverage divides by255/65535; floating EXR and NumPy values must already be finite coverage in [0,1]. Alpha never receives a colour transfer. `gray` means a two-dimensional coverage array. Four-channel `alpha` reads coverage only; `replicated_gray` requires all three channels to be exactly equal. Ambiguous RGB/other layouts are rejected. Binary masks accept only0/1 after declared decoding, with no implicit threshold. Lossy images and encoded video are unsupported. Actual uint16 PNG and float EXR roundtrips are tested. Native decoder errors are contextual data errors with their causes retained; no alternate decoder/fallback is selected.

Reports record manifest-byte SHA256, per-frame role/path/hash/shape/dtype/channel, selected IDs/FPS, optional source identity, reference provenance and explicit metric definitions/populations. Every frame is hashed before and after decoding; changes fail. This proves stable individual reads, not a globally atomic media snapshot or encoded/VFR timing. CLI reports cannot overwrite the manifest, input frames or source, or be placed inside a source frame directory. Failed evaluation preserves an existing atomic report. OpenCV EXR support must actually be available; missing codecs are errors, not passing checks.

The generated two-frame/four-pixel PNG/EXR CLI fixture records candidate MAE0.25, baselineMAE1 and delta−0.75 in `benchmark-results/alpha-m10-generated-sequence.json`. These are known arithmetic values, not inference/quality improvement measurements. Reference geometry/channel/range checks do not prove that an author aligned the right photographic frames.

Benchmark integration is described in `benchmark.md`. Linear foreground/composite evaluation is implemented below; motion-compensated temporal alpha metrics are implemented below; decoded-video evaluation, blinded review and real held-out/model quality acceptance remain unfinished. The evaluation ledger task remains in progress.

## Foreground and composite reference evaluation — milestone 11

`evaluation_colour.colour_metrics` supports explicitly declared `linear_srgb_bt709` RGB in H×W×3 or T×H×W×3 arrays, with matching coverage alpha and declared straight/premultiplied associations for candidate/reference. It performs no primaries/transfer transform, clipping or peak normalization. Signed and above-one RGB are valid. Other colour spaces require an explicit future transform, not relabelling. Invalid nonfinite inputs or arithmetic overflow are errors; masked-out samples do not participate in error/composite arithmetic.

Foreground MAE is the float64 sum of absolute straight-RGB channel errors divided by three times evaluated foreground pixels. It requires a supplied boolean valid-reference foreground mask and additionally excludes reference alpha≤the declared unpremultiply epsilon (default1e-6). Excluded reference pixels are counted. Premultiplied colour divides by alpha only above epsilon; below it, straight RGB is explicitly zero. Such selected candidate pixels remain scored and are counted as undefined; they are not dropped to improve a score. Premultiplied RGB must be zero at exactly zero alpha. Straight-input RGB is compared directly in valid reference regions. Alpha accuracy accompanies colour metrics so a low colour error alone cannot hide a poor matte.

Composite MAE uses the same declared linear RGB background for candidate/reference: premultiplied foreground + background×(1−coverage). Background may be a constant triplet or a matching image. Its denominator is three times selected composite pixels; the composite mask defaults to all pixels. No background means this metric is unavailable; no foreground mask means foreground error is unavailable. Missing references/empty populations produce nulls with reasons. Units are linear RGB/channel, not perceptual scores. Negative baseline/candidate deltas mean lower error for those declared units/regions only.

`ColourAccumulator` and `compare_colour_stream` sum channel errors/populations and alpha errors over frames, retain no clip-length image buffers and expose foreground/composite availability separately. Accumulation overflow rejects the new frame before changing prior sums/counts. Metadata scales with frame count, and large individual images still require sufficient memory.

```sh
python -m corridorkey.evaluation_colour_media colour-manifest.json \
  --output benchmark-results/colour-comparison.json
```

Use `benchmarks/suites/colour-sequence.example.json` after filling actual local paths, provenance and alignment. Each selected frame explicitly pairs candidate RGB/alpha and optional reference/baseline RGB/alpha, plus optional foreground/composite masks and per-frame background. A constant root background and per-frame background are mutually exclusive. Roles remain constant, IDs increase, and FPS is declared. Associations, `rgb`/`rgba` layouts and alpha-channel extraction are explicit. References require author/origin/permitted-use/split declarations; these record user assertions, not independent legal or ground-truth verification.

RGB readers support NPY, PNG and EXR. NPY uses RGB(A) order and declared linear units; OpenCV PNG/EXR BGR(A) becomes RGB(A). Integer PNG RGB divides by255/65535. These PNG values are interpreted as **explicitly declared linear data**, never automatically sRGB-decoded. Floating RGB keeps signed/HDR values. RGBA layout extracts the RGB channels; alpha is the separately declared asset/role, optionally the same RGBA file with alpha-channel extraction. Missing codecs/corrupt input/nonfinite data fail without alternate decoding. Hashes before/after reads, source/manifest identities, reference provenance, input protection and atomic report preservation mirror alpha evaluation. Stable reads do not certify globally atomic media, correct photographic alignment, embedded colour metadata or encoded/VFR timing.

Generated two-frame premultiplied EXR/PNG CLI fixture: foreground MAE0.25 (6 channel samples), composite MAE0.0625 (12 samples), deltas−0.75/−0.9375 in `benchmark-results/colour-m11-generated-sequence.json`. These known arithmetic values are not a processing enhancement or photographic/held-out quality measurement. Tests cover association/HDR/negative values, masks/undefined colour, missing prerequisites, weighted streaming populations, array release, RGB channel order/uint16 levels, actual file decoding, atomic CLI behavior, overflow and native export binding. Motion/occlusion-aware temporal alpha evaluation is implemented below; independent flow quality and real blinded/held-out review remain open.

## Motion-compensated temporal reference evaluation — milestone 12

`evaluation_temporal.temporal_pair` samples previous alpha using a declared current-to-previous native displacement field: at current pixel(x,y), sample previous(x+dx,y+dy). Flow arrays are finite H×W×2 in xy pixel units, without resizing, normalized coordinates or estimation. Float64 bilinear sampling excludes out-of-bounds coordinates. A supplied boolean current visibility mask must exclude occluded/disoccluded correspondences; absence makes temporal metrics unavailable. Previous/current evaluation masks additionally exclude current invalid pixels and any nonzero-weight invalid previous interpolation neighbor. Optional previous-to-current flow adds a forward/backward consistency gate using the declared native-pixel threshold. These masks/flows are data, not calibrated confidence.

Temporal residual MAE is mean(abs((prediction_now−warp(prediction_previous))−(reference_now−warp(reference_previous)))) over valid visible correspondences. Its range is0..2 for coverage alpha; units are alpha/pixel pair, not per-second. Candidate/reference motion-compensated change MAEs are separate diagnostics. No reference means no reference residual; diagnostic change may still be measurable. Cuts/resets are explicitly excluded with null temporal values, while spatial error remains evaluated. Missing flow, missing visibility or no valid correspondences yields nulls/reasons/populations rather than a fake zero. Supplied forward flow and actually performed consistency checks have separate flags.

Spatial alpha accuracy accompanies every pair and full sequence. A blank matte can have zero temporal residual under correct translating flow while remaining spatially wrong; the analytic frozen/blank test demonstrates this. Never infer quality from smoothness/residual alone. Visibility, consistency, masks and boundary exclusions can overlap; counters explain evaluated populations but are not additive disjoint partitions.

`TemporalAccumulator` owns independent copies of preceding alpha/reference/mask so a decoder reusing buffers cannot alter prior frames. Spatial frame errors contribute once; temporal pair errors sum by valid pixels, not by equally weighted pair means. Scalar per-pair metadata grows with clip length; image buffers stay bounded. Frame IDs increase. Nonconsecutive flow requires an explicit preceding selected-frame link; first selected frames have no preceding transition. Settings/cut/link types are validated even for singleton streams. Returned geometry/history snapshots do not alias internal state.

```sh
python -m corridorkey.evaluation_temporal_media temporal-manifest.json \
  --output benchmark-results/temporal-comparison.json
```

Use `benchmarks/suites/temporal-sequence.example.json` with actual local assets and provenance. Alpha/reference/baseline/mask use the existing normalized NPY/PNG/EXR decoder. Flow must be a native H×W×2 `.npy`, loaded without pickle; visibility must be binary. Every flow transition declares `flow_previous_frame`. `cut:true` frames must omit unused transition assets/link; first frames also cannot declare them. Root flow convention and method/origin/visibility-definition/candidate-independent declarations are required when flow exists. These record user assertions, not independent flow/occlusion validation. Missing transitions remain explicitly unavailable; no estimator or shot detector is selected implicitly.

Reports retain source/reference/flow/visibility/manifest hashes, selected IDs/FPS, provenance, pair exclusion counts/reasons, spatial and temporal populations, and baseline deltas. Individual stable reads do not prove a globally atomic snapshot, correct correspondence or VFR/encoded timing. CLI input/source/manifest protection and atomic failure preservation include flow assets. FPS is metadata; different pair intervals must not be conflated with a per-second metric.

Actual generated three-frame/six-pixel CLI: spatial MAE2/3, temporal residual0.5 over4 valid pair pixels, baseline deltas+2/3 and+0.5 (`benchmark-results/temporal-m12-generated-sequence.json`). These are known arithmetic values, not real-footage or model-performance measurements. Tests cover translation/subpixel flow, blank/frozen counterexamples, occlusion masks/invalid stencil samples, consistency, cuts/missing data, reused buffers, gaps, singleton validation, snapshot ownership, actual flow files/CLI and completed EXR binding. Real independent flow/occlusion accuracy, held-out/blinded review and GPU/model quality remain unverified.
