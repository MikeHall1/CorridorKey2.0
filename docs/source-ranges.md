# Source ranges and synchronized comparison

`InferenceConfig.start_frame` / `--start_frame` is optional (default null). An explicit nonnegative, zero-based source index requires `start_mode=begin`; it never combines with middle/random selection. `num_frames>0` limits frames after that index; zero/negative means the remainder. A limit extending beyond EOF keeps the existing cap-at-EOF behavior. An in frame at/past EOF rejects. Both video and naturally ordered frame directories support explicit starts. Existing null-start begin/middle/random video behavior remains unchanged; directories still reject middle/random.

The actual `diagnostics.source.start_frame` and `num_frames` define the selected half-open range. Export frame0 corresponds to that source start. All engine temporal indices (Quick Key cuts/anchors/resets and correction frames/ranges) remain relative to the selected clip. RVM starts fresh at the selected in frame; this does not reconstruct earlier full-source state or guarantee equality with a longer render. Full hint directories/videos align to the actual source offset; first-frame hints apply to the first selected frame.

Correction authoring uses the same probe and binds source start/count/geometry/FPS. Changing render selection requires compatible/rebound corrections. Existing correction documents and queued requests are not rewritten. Config serialization/provenance/cache identities carry the new field; conservative implementation identities invalidate old intermediate reuse when code changes.

For synchronized desktop comparison, select a completed normal render and an export view, then **Selected render as synchronized A**. A retains that render's observed range, export paths and chosen view. Select another completed row for B or choose Source. The frame control now addresses absolute source indices. Both thumbnails decode in one latest-request-only background operation and publish together. A's view stays fixed; B's view can change. Clear A exits this mode; fixed thumbnail pinning remains available.

Different render starts map the same absolute source index to different output-relative indices. Completed render A/B must have the same source path, native geometry and compatible FPS and overlapping ranges. Source B must use A's source path. Missing historical source metadata is rejected rather than guessing a middle/random offset. Current exports must still have the recorded count/geometry. Missing exports, out-of-overlap requests and decode failures reject the pair; stale in-flight results cannot populate an invalid selection.

This is frame-index/source-path alignment, not authenticated media identity, timestamp/VFR alignment, real-time playback, model quality approval or a managed arbitrary-primaries viewer. Keep media/exports stable; current bytes are decoded. Existing OpenCV video limitations and explicit source/export colour conversion apply. CPU generated fixtures verify orchestration; real GPU, encoded timing and visual acceptance remain NOT VERIFIED.

Desktop **Source In / Out (exclusive)** applies `start_frame=In`, `num_frames=Out-In`, `start_mode=begin` to future jobs only. Blank Out selects the remaining source. Apply validates the complete configuration before replacing text; reversed/empty ranges fail without changing it. **Mark In/Mark Out** stage the current frame position (Out is position+1); a completed export position is translated using its observed start offset. Synchronized mode already uses source coordinates. Apply is explicit and never submits. Projects retain the core range; queued snapshots remain unchanged. Choosing a legacy middle/random start clears explicit start. Existing frame-limit edits limit the current explicit start. Source EOF caps requested Out, and actual diagnostics record the resulting range.

Video source/prepass/draft/hint readers reject a reported decoder seek refusal and release the capture before any frame is processed. This admission check is not proof of exact seeking for every codec or variable-rate timestamp alignment.
